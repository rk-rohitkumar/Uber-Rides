# Documentation maintenance

Documentation is part of the project deliverable.

Update docs when changes affect:
- business logic
- semantic model structure
- measure definitions or purpose
- naming conventions
- report navigation or page purpose
- assumptions, limitations, or known issues
- onboarding / handover clarity

Documentation principles:
- Keep documentation concise, specific, and implementation-aware.
- Prefer practical explanations over generic theory.
- Record the "why" for important modeling or reporting decisions.
- If a new object is added, update the most relevant existing document instead of scattering notes across many files.
- Use change-log.md for incremental updates and agent-handover.md for current working context.
