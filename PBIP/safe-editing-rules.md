# Safe Editing Rules for PBIP Projects

These rules capture Microsoft guidance on what is safe or risky when editing PBIP files outside Power BI Desktop.[file:137]

## General safety principles

- Prefer reading and analysis first; perform small, targeted edits.[file:137]
- After making external changes, restart Power BI Desktop so it reloads project files.[file:137]
- Save edited files as UTF‑8 without BOM and keep CRLF line endings to avoid Git EOL noise on Windows.[file:137]
- Use a short root folder path to reduce the chance of hitting the 260‑character Windows path limit for nested PBIP files.[file:137]
- Avoid saving PBIP directly to OneDrive or SharePoint locations because sync issues can cause failed saves.[file:137]

## Files that should not be externally edited (preview)

During preview, **do not externally edit** these files unless Microsoft updates the guidance:[file:137]

- `report.json` – PBIR‑Legacy report definition.[file:137]
- `mobileState.json` – mobile rendering metadata.[file:137]
- `semanticModelDiagramLayout.json` / `diagramLayout.json` – diagram layout metadata.[file:137]
- `SemanticModel.json` – undocumented semantic model metadata.[file:137]

Changes to these files can cause errors or prevent the project from opening in Desktop.[file:137]

## Semantic model cautions

- All semantic model metadata is readable; write operations via external tools are supported but can cause inconsistencies if misused.[file:137]
- Do not modify automatic date tables generated by Power BI using external tools.[file:137]
- If `unappliedChanges.json` exists, applying those pending changes in Desktop overwrites existing semantic model queries, potentially discarding external edits.[file:137]
- For composite/Direct Lake models, user customizations may require `changedProperties` and `PBIRemovedChildren` tags so they persist across schema synchronizations.[file:137]

## Report cautions

- PBIR (enhanced report format) files can be edited as long as they conform to their JSON schemas.[file:137]
- Invalid schemas or missing required properties can cause **blocking errors** that prevent the report from opening.[file:137]
- Some misconfigurations, like invalid `activePageName`, are **non‑blocking** and may be auto-corrected by Desktop but should still be reviewed.[file:137]
- PBIR files can contain persisted data values (e.g., slicer selections, filters), so treat them as potentially sensitive.[file:137]

## Source-control cautions

- Treat `cache.abf` and user-local settings as runtime artifacts, not as the source of truth.[file:137]
- Keep `.gitignore` in sync with Microsoft’s defaults to avoid committing local caches and environment-specific files.[file:137]
- Consider whether `unappliedChanges.json` should be tracked or ignored depending on team workflow around unfinished Power Query changes.[file:137]
